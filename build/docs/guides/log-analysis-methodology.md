## Quick Validation Checklist

**Prerequisites:** Capture logs using `../../scripts/logging/monitor-transcript-queues.sh` first.

Given a log file from `monitor-transcript-queues.sh` or similar, validate each component:

```bash
LOG="/tmp/transcript-queue-monitor-*.log"  # Generated by ../../scripts/logging/monitor-transcript-queues.sh

# 1. Discovery works
grep -c "DISCOVERY-ORDER" $LOG  # Should be >0

# 2. Hoovering completes
STARTS=$(grep -c "HOOVER-START" $LOG)
DONES=$(grep -c "HOOVER-DONE" $LOG)
echo "Starts: $STARTS, Dones: $DONES"  # Should match (no hangs)

# 3. Database insertions work
grep -c "HOOVER-BATCH-INSERT-DONE" $LOG  # Should be >0 for large projects

# 4. Timeline loads
grep -c "TIMELINE-LOAD" $LOG  # Should be >0

# 5. Timeline updates UI
grep -c "TIMELINE-APPEND" $LOG  # Should be >0
```

**Pass criteria:** All counts >0, HOOVER-START = HOOVER-DONE

## Core Tag Reference

### Discovery Tags

**`[DISCOVERY-ORDER]`** - Project discovery sorted by newest
```bash
grep "DISCOVERY-ORDER" $LOG | head -1
```
**Validates:** Newest project discovered first
**Measure:** Order of project names
**Expected:** `Top 3 by activity: <newest-project> (mtime: <recent-date>), ...`

**`[DISC-PROJECT-QUEUE]`** - Transcripts queued for hoovering
```bash
grep "DISC-PROJECT-QUEUE" $LOG
```
**Validates:** Transcripts discovered and queued
**Measure:** Count of queued transcripts per project
**Expected:** `Prepared N transcripts for deferred ingestion`

### Hoovering Tags

**`[HOOVER-START]`** - Hoovering begins for transcript
```bash
grep "HOOVER-START" $LOG | wc -l
```
**Validates:** Hoovering initiated
**Measure:** Count of started transcripts
**Expected:** >0 (should match HOOVER-DONE count)

**`[HOOVER-DONE]`** - Hoovering completes successfully
```bash
grep "HOOVER-DONE" $LOG | wc -l
```
**Validates:** Hoovering completed without hang
**Measure:** Count of completed transcripts
**Expected:** Equals HOOVER-START count (100% completion)

**Critical check:**
```bash
STARTS=$(grep -c "HOOVER-START" $LOG)
DONES=$(grep -c "HOOVER-DONE" $LOG)
if [ $STARTS -eq $DONES ]; then
    echo "✅ No hangs detected"
else
    echo "❌ Potential hang: $STARTS started, $DONES completed"
fi
```

**`[HOOVER-SKIP-LARGE]`** - Large line skipped (>50KB)
```bash
grep "HOOVER-SKIP-LARGE" $LOG | head -5
```
**Validates:** Parser handles large JSON payloads
**Measure:** Count and sizes of large lines
**Expected:** >0 for projects with Edit/Read tool results
**Note:** These are SKIPPED (tool_result entries not stored), not errors

**`[HOOVER-INNER-COMPLETE]`** - Inner parsing loop completed
```bash
grep "HOOVER-INNER-COMPLETE" $LOG | wc -l
```
**Validates:** Parser never hangs in inner loop
**Measure:** Count of loop completions
**Expected:** Many (one per buffer drain iteration)
**Diagnostic:** If count is low but HOOVER-START is high, parser may be stuck

**`[HOOVER-BATCH-INSERT-START]`** / **`[HOOVER-BATCH-INSERT-DONE]`**
```bash
grep "HOOVER-BATCH-INSERT-START" $LOG | wc -l
grep "HOOVER-BATCH-INSERT-DONE" $LOG | wc -l
```
**Validates:** Database batch operations complete
**Measure:** Count and duration
**Expected:** Start count = Done count, duration <5s per batch
**Check duration:**
```bash
grep "HOOVER-BATCH-INSERT-DONE" $LOG | grep -o "[0-9]*ms" | head -5
```

### Timeline Tags

**`[TIMELINE-LOAD]`** - Timeline querying database
```bash
grep "TIMELINE-LOAD" $LOG | wc -l
```
**Validates:** Timeline actively loading
**Measure:** Load frequency
**Expected:** >0, multiple loads during hoovering

**`[TIMELINE-APPEND]`** - Timeline updating UI
```bash
grep "TIMELINE-APPEND" $LOG | wc -l
```
**Validates:** UI actually updates
**Measure:** Count of UI updates
**Expected:** >0, should be ≤ TIMELINE-LOAD count

**`[TIMELINE-SKIP]` / `[TIMELINE-SKIP-DISABLED]`** - Skip optimization
```bash
grep "TIMELINE-SKIP" $LOG | wc -l
```
**Validates:** Skip optimization behavior
**Measure:** Skip frequency
**Expected:** After fix, should see TIMELINE-SKIP-DISABLED instead
**Note:** High TIMELINE-SKIP count = timeline not refreshing (bug)

### Progress Tags

**`[HOOVER-PROGRESS]`** - Hoovering progress updates
```bash
grep "HOOVER-PROGRESS" $LOG | tail -10
```
**Validates:** Hoovering progressing
**Measure:** Completed vs total count
**Expected:** `completed=N/M` with N increasing over time

## Measurement Patterns

### 1. Completion Rate (Detect Hangs)

**Purpose:** Verify no transcripts hang during hoovering

```bash
STARTS=$(grep -c "HOOVER-START" $LOG)
DONES=$(grep -c "HOOVER-DONE" $LOG)
RATE=$(awk "BEGIN {printf \"%.1f\", ($DONES/$STARTS)*100}")
echo "Completion rate: $RATE% ($DONES/$STARTS)"
```

**Pass criteria:** 100% (all started hooverings complete)
**Fail:** <100% = some transcripts hung

### 2. Sequence Validation (Correct Order)

**Purpose:** Verify events happen in correct order

**Pattern:** Event A must happen before Event B

```bash
# Example: HOOVER-START before HOOVER-DONE for same transcript
grep "HOOVER.*7DEF49DE" $LOG | grep -E "START|DONE"
```

**Expected output:**
```
[HOOVER-START] ... 7DEF49DE ...
[HOOVER-DONE] ... 7DEF49DE ...
```

**Common sequences to validate:**
- DISCOVERY-ORDER → DISC-PROJECT-QUEUE → HOOVER-START → HOOVER-DONE
- HOOVER-DONE → TIMELINE-LOAD → TIMELINE-APPEND
- HOOVER-BATCH-INSERT-START → HOOVER-BATCH-INSERT-DONE

### 3. Timing Analysis (Performance)

**Purpose:** Measure operation duration

**Pattern:** Calculate time between START/DONE pairs

```bash
# Extract timestamps and calculate duration
grep "HOOVER-BATCH-INSERT" $LOG | \
  grep -E "START|DONE" | \
  awk '{print $1, $2, $NF}'
```

**For precise timing:**
```bash
# If logs include duration in message
grep "HOOVER-DONE.*in.*ms" $LOG | \
  grep -o "[0-9]* new lines.*in [0-9]*ms" | \
  awk '{print "Lines:", $1, "Time:", $4}'
```

**Thresholds:**
- Batch insert: <5s acceptable, >5s = warning
- Full hoover: <1s for small transcripts, <5s for large
- Timeline load: <100ms for 25 entries

### 4. Data Freshness (Timeline Shows Recent)

**Purpose:** Verify timeline shows newly hoovered entries

**Method:** Check if timeline loads AFTER hoovering completes

```bash
# Get hoovering completion time for specific transcript
HOOVER_TIME=$(grep "HOOVER-DONE.*7DEF49DE" $LOG | awk '{print $1, $2}' | head -1)

# Check if timeline loaded after that time
grep "TIMELINE-LOAD" $LOG | \
  awk -v ht="$HOOVER_TIME" '$1" "$2 > ht {print "Timeline loaded AFTER hoover:", $1, $2}'
```

**Expected:** At least one timeline load after hoovering
**Fail:** No loads after hoover = timeline not refreshing

### 5. Tag Correlation (Cross-Component)

**Purpose:** Verify data flows through entire pipeline

**Method:** Track specific transcript ID through all stages

```bash
TRANSCRIPT="7DEF49DE-4F9D-4D8A-AE6C-3BAF4E357749"

echo "=== Pipeline for $TRANSCRIPT ==="
echo "Discovery:"
grep "$TRANSCRIPT" $LOG | grep "DISC-PROJECT"
echo ""
echo "Hoovering:"
grep "$TRANSCRIPT" $LOG | grep -E "HOOVER-START|HOOVER-DONE"
echo ""
echo "Database:"
grep "$TRANSCRIPT" $LOG | grep "DB-UPDATE"
echo ""
echo "Timeline:"
# Timeline uses project ID, not transcript ID
# Need to map transcript → project → timeline loads
```

**Expected:** Tags appear for all stages (discovery → hoover → DB → timeline)

## Common Analysis Workflows

### Workflow 1: "Feature Not Appearing"

**Symptom:** User says "recent conversation not in timeline"

**Analysis:**
```bash
# 1. Verify hoovering completed
grep "HOOVER-DONE" $LOG | wc -l  # Should be >0

# 2. Verify database insertions
grep "DB-UPDATE.*entries=" $LOG | tail -5  # Should show recent entries

# 3. Verify timeline loaded
grep "TIMELINE-LOAD" $LOG | wc -l  # Should be >0

# 4. Check for skip bug
grep "TIMELINE-SKIP.*unchanged" $LOG | wc -l  # Should be 0 (after fix)

# 5. Identify broken stage
echo "Discovery: $(grep -c DISCOVERY-ORDER $LOG)"
echo "Hoovering: $(grep -c HOOVER-DONE $LOG)"
echo "DB Updates: $(grep -c DB-UPDATE $LOG)"
echo "Timeline Loads: $(grep -c TIMELINE-LOAD $LOG)"
echo "UI Updates: $(grep -c TIMELINE-APPEND $LOG)"
```

**Diagnosis:**
- Discovery=0: Project not found
- Hoovering=0: No transcripts hoovered
- DB Updates=0: Database writes failing
- Timeline Loads=0: Timeline not monitoring
- UI Updates=0: Skip logic preventing refresh (THE BUG WE FOUND)

### Workflow 2: "App Slow/Hanging"

**Symptom:** User says "app hangs at 100% CPU"

**Analysis:**
```bash
# 1. Check completion rate
STARTS=$(grep -c "HOOVER-START" $LOG)
DONES=$(grep -c "HOOVER-DONE" $LOG)
echo "Starts: $STARTS, Dones: $DONES"

# 2. If mismatched, find stuck transcript
grep "HOOVER-START" $LOG | awk '{print $NF}' | sort > /tmp/starts.txt
grep "HOOVER-DONE" $LOG | awk '{print $NF}' | sort > /tmp/dones.txt
comm -23 /tmp/starts.txt /tmp/dones.txt  # Shows stuck transcripts

# 3. Check where it stuck
STUCK=$(comm -23 /tmp/starts.txt /tmp/dones.txt | head -1)
grep "$STUCK" $LOG | grep "HOOVER"

# 4. Look for last activity
grep "$STUCK" $LOG | tail -20
```

**Diagnosis:**
- HOOVER-START but no HOOVER-DONE: Hung during hoovering
- Last log is HOOVER-INNER-COMPLETE: Hung in outer loop
- Last log is HOOVER-BATCH-INSERT-START: Hung in DB operation
- Last log is HOOVER-SKIP-LARGE: Processing large line

### Workflow 3: "Validate Fix Works"

**Symptom:** Testing after bug fix

**Analysis:**
```bash
# Before fix - what we expect to see in old logs
grep "TIMELINE-SKIP.*unchanged" old.log | wc -l  # High count = bug present

# After fix - what we expect to see in new logs
grep "TIMELINE-SKIP-DISABLED" new.log | wc -l  # Should be >0
grep "TIMELINE-SKIP.*unchanged" new.log | wc -l  # Should be 0

# Verify timeline actually updates
grep "TIMELINE-APPEND" new.log | wc -l  # Should equal TIMELINE-LOAD count
```

## Automated Validation Script Template

```bash
#!/bin/bash
# Quick log validation for hoovering + timeline
set -euo pipefail

LOG="${1:-/tmp/transcript-queue-monitor-*.log}"

echo "=== VALIDATION REPORT ==="
echo "Log: $LOG"
echo ""

# Hoovering
STARTS=$(grep -c "HOOVER-START" "$LOG" || echo "0")
DONES=$(grep -c "HOOVER-DONE" "$LOG" || echo "0")
echo "Hoovering:"
echo "  Starts: $STARTS"
echo "  Dones:  $DONES"
if [ "$STARTS" -eq "$DONES" ]; then
    echo "  Status: ✅ All completed"
else
    echo "  Status: ❌ $((STARTS - DONES)) hung"
fi
echo ""

# Discovery
DISCO=$(grep -c "DISCOVERY-ORDER" "$LOG" || echo "0")
echo "Discovery:"
echo "  Events: $DISCO"
echo "  Status: $([ $DISCO -gt 0 ] && echo '✅ Active' || echo '❌ Not found')"
echo ""

# Database
DB_INSERTS=$(grep -c "DB-UPDATE" "$LOG" || echo "0")
echo "Database:"
echo "  Inserts: $DB_INSERTS"
echo "  Status: $([ $DB_INSERTS -gt 0 ] && echo '✅ Active' || echo '❌ No writes')"
echo ""

# Timeline
TL_LOADS=$(grep -c "TIMELINE-LOAD" "$LOG" || echo "0")
TL_APPENDS=$(grep -c "TIMELINE-APPEND" "$LOG" || echo "0")
TL_SKIPS=$(grep -c "TIMELINE-SKIP.*unchanged" "$LOG" || echo "0")
echo "Timeline:"
echo "  Loads:   $TL_LOADS"
echo "  Appends: $TL_APPENDS"
echo "  Skips:   $TL_SKIPS"
if [ $TL_APPENDS -gt 0 ]; then
    echo "  Status: ✅ Updating"
elif [ $TL_SKIPS -gt 10 ]; then
    echo "  Status: ⚠️  High skip count (possible bug)"
else
    echo "  Status: ❌ Not updating"
fi
echo ""

# Overall
echo "=== OVERALL ==="
TOTAL_CHECKS=4
PASSED=0
[ "$STARTS" -eq "$DONES" ] && PASSED=$((PASSED + 1))
[ $DISCO -gt 0 ] && PASSED=$((PASSED + 1))
[ $DB_INSERTS -gt 0 ] && PASSED=$((PASSED + 1))
[ $TL_APPENDS -gt 0 ] && PASSED=$((PASSED + 1))

echo "Passed: $PASSED/$TOTAL_CHECKS"
if [ $PASSED -eq $TOTAL_CHECKS ]; then
    echo "✅ ALL SYSTEMS OPERATIONAL"
    exit 0
else
    echo "❌ SOME SYSTEMS FAILING"
    exit 1
fi
```

## Tag Evolution & Documentation

### Adding New Diagnostic Tags

When adding new instrumentation, document here:

**Format:**
```
[TAG-NAME] - Brief description
Location: File.swift:line
Purpose: What this validates
Measure: What to count/time
Example: grep "TAG-NAME" log
```

**Recent additions (2025-11-16):**
- `[HOOVER-SKIP-LARGE]` - Large line skipping (>50KB)
- `[HOOVER-INNER-COMPLETE]` - Inner loop completions
- `[HOOVER-BATCH-INSERT-START/DONE]` - Batch insertion timing
- `[TIMELINE-SKIP-DISABLED]` - Skip optimization disabled

### Tag Naming Conventions

**Pattern:** `[COMPONENT-EVENT]` or `[COMPONENT-STATE]`

**Components:**
- DISCOVERY - Project/transcript discovery
- HOOVER - Transcript hoovering/ingestion
- TIMELINE - Timeline loading/display
- DB / DATABASE - Database operations
- SUMM - Summary generation
- VIEWPORT - Viewport tracking

**Events:**
- START/DONE - Lifecycle pairs
- SKIP - Optimization skipped operation
- ERROR - Error occurred
- PROGRESS - Progress update

**States:**
- ORDER - Sorted list
- COMPLETE - Completion state
- UPDATE - State changed

## Common Pitfalls

### 1. Searching by Filename Instead of DB ID

**Wrong:**
```bash
grep "c6a664ec-d3f9-4658-bf45-6324f80edfb6" $LOG  # Filename
```

**Right:**
```bash
grep "7DEF49DE-4F9D-4D8A-AE6C-3BAF4E357749" $LOG  # Database transcript ID
```

**Why:** Logs use database IDs, not filenames. Get ID from:
```bash
grep "c6a664ec" $LOG | grep "TRANS-DISC-UPSERT.*ID:"
```

### 2. Comparing Apples to Oranges

**Wrong:** Comparing message timestamp to file mtime
- Message timestamp = when message was sent
- File mtime = when file was last written

**Right:** Understand what timeline sorts by (message timestamp, not hoover time)

### 3. Not Accounting for Clean DB Tests

Clean DB tests show different behavior than normal operation:
- Discovery takes longer (must find all projects)
- Large projects may not be discovered in test window
- Timeline starts empty (no existing entries)

**Validate with:** Both clean DB test AND normal operation test
